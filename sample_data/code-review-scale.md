Code review was built for a world where a human wrote every line. That assumption no longer holds, and the review process hasn't caught up.

When AI generates a meaningful share of a codebase's changes, the review bottleneck shifts. It's no longer about catching typos or style violations. It's about verifying intent: does this code actually do what the team meant for it to do, and does the reviewer have enough context to judge that quickly.

Most teams are still running code review as if volume hasn't changed. The result is a queue that grows faster than reviewers can process it, and a growing gap between "this was merged" and "someone actually understood it."

The fix isn't more reviewers. It's rethinking what review is for when the bottleneck moves from writing code to verifying it.
